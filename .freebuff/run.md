# Run doc — ApartmentPro (apartment-management-saas)

Two processes: an Express + Prisma API (`backend`, port 3001) and a Svelte 5 + Vite SPA
(`frontend`, port 5173). The SPA talks to the API directly through `VITE_API_URL`;
there is no Vite proxy.

## 1. Reproduce the uncommitted artifacts

A fresh checkout needs two untracked files and installed dependencies.

1. Copy the env files from the main checkout (`C:\Users\deel\apartment-management-saas`)
   — copy, never symlink, because ports and database URLs may need adapting per worktree:
   - `backend/.env` (required: `DATABASE_URL`; the server reads no `PORT`, see below)
   - `frontend/.env` (optional: `VITE_API_URL`, defaults to `http://localhost:3001/api`)
2. Install dependencies with npm (both lockfiles are `package-lock.json`):
   - `cd frontend && npm install`
   - `cd backend && npm install`
3. The Prisma client is generated by `npm install` (backend `postinstall`); if the schema
   changed, run `cd backend && npx prisma generate`. Apply migrations only when the task
   calls for it — this worktree shares the main checkout's database.

## 2. Run the servers

Backend (port 3001, hard-coded in `backend/src/server.js`):

```
cd backend && npm run dev        # nodemon src/server.js
```

Frontend (Vite, port 5173 — the project default):

```
cd frontend && npm run dev       # vite
```

Detach them so they outlive the conversation. On Windows start PowerShell and use the pid
it prints; name the executable exactly (`npm.cmd`, not `npm`), and send stdout and stderr to
**different** files:

```
powershell -NoProfile -Command "(Start-Process -FilePath 'npm.cmd' -ArgumentList 'run','dev' -WorkingDirectory '<dir>' -RedirectStandardOutput '<log>' -RedirectStandardError '<log>.err' -WindowStyle Hidden -PassThru).Id"
```

Then confirm it survived with `powershell -NoProfile -Command "Get-Process -Id <pid>"` and
wait until `http://localhost:5173/` answers before registering the preview.

Logs for the current preview: `.freebuff/preview-119c445e-83ed-4451-9dca-6e8c358fec09.log`
(and `.log.err`).

## Notes learned the hard way

- The API is on **3001**, not 3000 — `curl http://localhost:3001/api/health` to check it.
- The startup language defaults to Persian (`fa`, RTL) unless
  `localStorage['apartmentpro.language']` is set; navigate with a query string
  (`/?x=1#/route`) to force a real reload after changing it, since a hash-only change does
  not re-initialise the i18n store.
- Seeded login for local work: `admin@example.com` / `Admin@123456` (dev-only seed
  defaults). Repeated logins can trip the rate limiter (429) — space them out.
- Registering a preview with `replace: true` stops the previous preview's server; the Vite
  dev server has to be started again afterwards.
- `/api/auth/login` is rate-limited to **10 attempts per 15 minutes per IP** (in-memory,
  `auth.middleware.js`). A scripted harness that logs in on every run will hit 429; reuse one
  token instead, or restart the backend to clear the counter.
- In a Prisma `$transaction([...])` batch, an invalid predicate is reported against the
  **first** query in the array with the **last** query's field list — the blame is
  misleading. Check every model's own columns: `Floor`, `Meter`, `PaymentAllocation`,
  `InvoiceItem` and `JournalLine` have no `organizationId`, and `Payment`, `Journal`,
  `TenantAccount`, `TenantLedgerEntry` have no `deletedAt`.

## 3. Verifying the dashboard end to end

`.freebuff/cdp-dash.mjs` drives an isolated headless Chrome against the running servers:

```
node .freebuff/cdp-dash.mjs <lang> <width> <height> <out.png>
```

It logs in over the API (caching the token in `.freebuff/.dashboard-token` to stay under the
login rate limit), injects the cookie, opens `#/dashboard`, waits for real figures, then
writes a screenshot, `<out>-table.png` (the tenancy table scrolled into view, with a
hit test on every action control) and a JSON report on stdout.

To exercise the populated figures rather than an empty portfolio, create a throwaway
building → floor → apartments → tenant → lease → invoices → payments, then delete the ids
again including their posted journals, ledger entries and tenant account (the accounting
sides are written by the invoice and payment services, not by the dashboard).

## 4. The marketing landing page

`landing/index.html` is a standalone marketing page for **Apramt** (the product name used in
the landing brief). It is not part of the SPA and deliberately does not use the app's design
tokens — it is a marketing surface, not the console.

It needs **no server**: all four images are inlined as data URIs, so the page is one file that
renders with no network beyond the two Google webfonts (with system fallbacks).

- Preview: registered directly from `landing/index.html` (`register_preview` with `htmlPath`),
  so there is no process or port to keep alive.
- Source image assets live in `landing/img/` (`hero-apartment.jpg`, `avatar-1..3.jpg`). To switch
  back to file references, replace each `src="data:image/jpeg;base64,…"` with its
  `img/<name>.jpg` path — but see the trap below before doing it.
- The nav and footer CTAs point at the real app login, `http://localhost:5173/#/login`, so the
  page has to be opened on the same machine as the dev server.

Traps found while building it:

- **A local HTML preview serves that one file only** — relative `img/...` paths fail to load
  there (the image element reports `naturalWidth: 0`). Inline the assets, or serve the folder
  over HTTP.
- **`width`/`height` attributes are presentational hints, not just aspect-ratio inputs.** An
  `img` with `width: 100%` in CSS still rendered 1500px tall from its `height` attribute until
  `height: auto` was set explicitly.
- **`aspect-ratio` + `max-height` on an image fixes its intrinsic width**, which becomes the
  min-content of the grid/flex parent and stops that column from shrinking (the hero column
  refused to go below 511px on a 355px viewport). Give grid items `min-width: 0` and cap a
  photo by width, not height.
- **A shorthand `padding` cancels `.wrap`'s gutter** when both apply to the same element
  (`.footer-row` did exactly that with `padding: 22px 0`).
- `body { overflow-x: hidden }` hides genuine overflow from a `scrollWidth` check — measure
  element rects against the viewport as well.
- Chrome's headless CLI `--screenshot` only writes with an **absolute** output path, and
  `--window-size` can capture narrower than it laid out. When an exact width matters, drive CDP
  and set `Emulation.setDeviceMetricsOverride`.
- Anchor links to sections land under the fixed nav unless the sections carry `scroll-margin-top`.
- **Clean up scratch Chrome by pid, not by name.** `Get-Process chrome | Stop-Process` kills the
  user's own browser windows too.

## 5. The app home page (`/`) uses the Apramt landing design

The SPA's marketing root (`/`, and `/register`, which reuses the same component) is now built in
the landing brief's visual language — teal `#2f5b6b` + terracotta `#d98a4b`, Space Grotesk over
Inter, frosted glass, the hero photograph and the "rent roll" chip.

| Piece | Where |
|---|---|
| The page (markup + all of its CSS, class prefix `lp-`) | `frontend/src/pages/Home.svelte` |
| New copy (headline, stats, chip, reviews, 2 extra feature cards) | `frontend/src/i18n/{en,fa,ps}.js` under `home.*` |
| Hero photograph and the three portraits | `frontend/public/images/home/` |
| The two webfonts | `frontend/index.html` (Google Fonts; falls back to Vazirmatn) |
| The standalone marketing page (same design, inlined images, brand "Apramt") | `landing/index.html` |

The home page is deliberately **not** built from the console's design tokens: it is a marketing
surface, and `.lp-page` declares its own inside a scoped block. Everything else in the app is
untouched.

Traps specific to this page:

- **Svelte appends its scope class to type selectors too.** `.lp-menu button` compiles to
  `.lp-menu.svelte-x button.svelte-x` — specificity (0,2,1), which **outranks** `.lp-btn-primary`
  (0,2,0). That silently flattened the menu's CTA button until the rule became
  `button:not(.lp-btn)`. Watch for this whenever a scoped rule targets a bare element.
- The app's root font size is **14px**, not 16px. Every rem value carried over from the landing
  page rendered ~12.5% small, so the page's sizes are the landing's × 16/14.
- The `lp-` prefix is not cosmetic: Bootstrap already owns `.card`, `.badge`, `.btn`,
  `.btn-primary`, `.nav` and `.container` globally.
- **Do not put `overflow-x: hidden` on the page wrapper** — it becomes the scroll container and
  the sticky nav silently stops sticking.
- Below **620px** the language switcher and the nav CTA move into the hamburger panel; keeping
  the switcher in the pill overflowed it below ~355px (brand 149 + switcher 125 + toggle 44 >
  the 304px pill).
- The brief's four feature cards became **eight** here (the brief's four plus property, meters,
  invoices, expenses) so the page still describes the real product, in a 4-column grid.
- The three testimonials are **invented placeholders** (names, roles, quotes) — replace them
  with real customers or drop the section before this page is used publicly.

### 5.1 The hero is full-bleed (photograph behind the copy)

The hero is a full-bleed picture, not a two-column text + framed card: `.lp-hero-media` is
absolutely positioned under a `.lp-hero-veil` scrim, the copy sits above it in `.lp-hero-inner`,
and the nav is transparent while `scrolled` is false (`.lp-nav-over`) and returns to the normal
frosted pill once the page scrolls. Two traps that shape this:

- **The 14px root caps the headline.** `clamp(2.8rem, 5.6vw, 5.2rem)` tops out at **72.8px**, and
  the copy column must be wide enough for the *first* authored line on its own or the `<br />`
  between `hero.title` and `hero.titleAccent` yields three ragged lines instead of two. Hence
  `.lp-hero-content { max-width: min(54rem, 100%) }` while the lede keeps its own `32rem`.
- The scrim is mirrored in RTL with `:global([dir='rtl']) .lp-hero-veil { transform: scaleX(-1) }`
  because the copy moves to the other side of the photograph.
- The rent-roll chip is hidden at **≤1000px**; below that it would sit on top of the copy.
- The hero's own min-height is `clamp(560px, 88vh, 880px)` — on a short laptop viewport it hits
  the 560px floor and the copy compresses, which is the accepted trade-off.

## 6. The public auth pages (`/login`, `/register`)

Two standalone signed-out routes in `App.svelte`, wearing the landing page's identity rather than
the console's: a split layout with the hero photograph and a brand message on one side and a
frosted panel on the other, collapsing to a single centered column (photograph hidden) at 900px.
The landing page's *Get Started* buttons now point at `/register`; *Sign in* still points here.

| Shared `au-`-prefixed stylesheet for both pages | `frontend/src/styles/auth.css` (imported in `main.js`) |
| Sign in | `frontend/src/pages/Login.svelte` |
| Create account | `frontend/src/pages/Register.svelte` |
| Copy | `auth.*` (shared chrome), `login.*`, `register.*` in `en`/`fa`/`ps` |

The app's root font size is 14px here too, so the sizes are set for that.

- **There is no Google provider and no email verification in this API.** The Google button is
  present and explains itself (`auth.googleUnavailable`) instead of failing silently, and because
  `POST /auth/register` signs the new admin in immediately, the page shows a confirmation panel
  rather than a "check your inbox" message that would never arrive. Wiring either properly needs
  backend work first.
- `POST /auth/register` requires `organizationName`, `firstName`, `lastName`, `phone` and an 8+
  character password. The form asks for one full name and splits it; a single-word name is
  rejected client-side because the API requires a last name to be present.
- Reaching the success panel needs a real account, so exercise the API path with an email that
  already exists: the service checks for it *before* its transaction (line ~91 of
  `auth.service.js`), so a 409 creates nothing and still proves the error mapping.
- Bootstrap Icons do not mirror themselves — in RTL the back and continue arrows are flipped with
  `[dir='rtl'] .au-back i, .au-submit i { transform: scaleX(-1) }` in `auth.css`.
- The seeded demo account is `admin@example.com` / `Admin@123456` (`prisma/seed.js`), and the auth
  rate limit is shared by `/login` and `/register`, so a few attempts is all it takes to lock the
  IP out for 15 minutes.
